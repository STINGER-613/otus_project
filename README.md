Данный репозиторий содержит в себе файлы по настройке серверов 

Его основная задача:
- настроить веб сервер с балансировкой нагрузки через Nginx + Apache2
- настроить MySQL репликацию (master-slave)
- создавать бэкап БД со slave сервера (потаблично с указанием позиции бинлога)
- настроить систему мониторинга
- на основании скриптов, конфигов, cron файлов и бэкапов в максимально короткие сроки настроить новый сервер "с нуля"
- на чистом сервере за короткий промежуток времени получить полностью настроенную рабочую систему

При запуске скрипта BASH будет выполнена установка необходимого ПО и зависимостей
По окончанию настройки, скрипт выведет меню с выбором
В зависимости от того, какой сервер перед вами, нужно будет выбрать соответствующий пункт:

------------------------
1) Nginx (frontend)
2) Apache2 (backend)
3) Mysql (master)
4) Mysql (slave)
5) Monitoring + Logs
------------------------


Описание скриптаов:
- Nginx: отвечает за настройку сервиса, присваивая статический адрес 192.168.189.131 (если настройки сети и шлюза различны, просьба заменить на свои актуальные данные)
Выступает в роли Frontend в сторону 192.168.189.132

- Apache2: отвечает за настройку сервиса, присваивая статический адрес 192.168.189.132 (если настройки сети и шлюза различны, просьба заменить на свои актуальные данные)
Выступает в роли Backend в сторону 192.168.189.131

- Mysql_M: отвечает за настройку сервиса master, присваивая статический адрес 192.168.189.133 (если настройки сети и шлюза различны, просьба заменить на свои актуальные данные)
Выступает в роли «Master server», храня в себе актуальную информацию и настройки баз сервера

- Mysql_S: отвечает за настройку сервиса slave, присваивая статический адрес 192.168.189.134 (если настройки сети и шлюза различны, просьба заменить на свои актуальные данные)
Выступает в роли «Slave server», хроня в себе копии данных с «Master server», посредством копирования информации через «bin-lob и pos», обращаясь на него под учетной записью «otus» с паролем «qwe123» (обязательно заменить дефолтный пароль на свой перед созданием реплики)

- Monitoring: отвечает за настройку сервиса мониторинга, присваивая статический адрес 192.168.189.135 (если настройки сети и шлюза различны, просьба заменить на свои актуальные данные)
Выступает в роли «Мониторинга состояния сервера и служб», посредством запуска на нем Grafana и Prometheus в связке (метод реализации мониторинга представлен локально)

- Logs: отвечает за настройку сервиса логирования, присваивая статический адрес 192.168.189.136 (если настройки сети и шлюза различны, просьба заменить на свои актуальные данные)
Выступает в роли «logs_trash» или простым языком «сборщик событий или логов», основан на работе таких сервисов, как: elasticsearch, logstash, filebeat, kibana
При правильной реконструкции сервиса в ручном режиме, должен получиться сбор логов с отображением статистики в графическом режиме

- DB_BACKUP: отвечает за настройку бкапа, скрипт запускается через CRON с интервалом в 1ч. Данный скрипт должен храниться на "пятом" сервере, на котором развернут Monitoring + Logs, тогда при возникновении проблем на серверах 3 и 4, отвечающих за реплику, базы данных всегда будут в доступности
